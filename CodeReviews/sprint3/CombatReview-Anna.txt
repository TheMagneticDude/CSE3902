Specific comments on code quality: 

ICombatEntity is concise and contains only methods needed that are directly related to combat. The combat 
logic is organized well and the manager has just the basic methods needed, nothing too complicated. The Update method 
does handle a lot of different projectile, combat, and collision logic right now, which could get harder to maintain 
as more is added to the game. I like the design choice of using _swingHits so the enemies take damage correctly. The 
cohesion is good since everything in the class is combat-related. There is some coupling due to the fact that it is 
a manager and there are a lot things that CombatManager needs to interact with, but it is improved somewhat by the 
use of interfaces. 

A hypothetical change to make to the game related to file being reviewed 
and how the current implementation could or could not easily support that change:

If we wanted to add enemy projectiles that damage the player it would be pretty easy to implement with
what we have already. In Update the projectile collisions are already checked with the blocks and bosses, 
so we would just have to add a check for the player hitbox which would be pretty simple.
